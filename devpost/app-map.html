Lumi: App Map

A study lamp that notices when you sit down, counts down your focus time, pauses when you leave, and quizzes you on your own notes.

The three main pieces

The lamp

arduino/lumi_lamp/lumi_lamp.ino

Reads the distance sensor, runs the countdown, draws the eyes and text on the small screen, and plays the tune.

The web page

web/index.html

Talks to the lamp over USB (Web Serial), mirrors the timer, and runs the study buddy quiz.

The study server

server/server.js

Serves the page, stores uploaded notes, and asks Google Gemini to write and grade quiz questions.

Follow one action: a wrong answer becomes a weak spot on the lamp

Code route (reference)

Search for the names in code style to jump to each stop. Line numbers drift as the code changes; names don't.

  1. The page sends your answer. web/index.html, function quizAnswer. It shows "Checking your answer…", posts to /api/quiz/grade, and shows ✓ or ✗ with an explanation. If the AI fails, it puts your answer back so you can press Enter to try again.
  2. The server grades it with Gemini. server/server.js, route app.post('/api/quiz/grade'. It builds a short grading prompt and returns {correct, feedback}.
  3. The page decides it's a weak spot and tells Lumi. web/index.html, functions recordAnswer, lampReview, flagWeak. A topic is weak when you've missed it more often than you got it right. lampReview shortens the text to Lumi's 21 characters, and sendMsg sends it as an M message. On the lamp, arduino/lumi_lamp/lumi_lamp.ino handles kind == 'M' and shows the note for 4 seconds.

To change this, start here

  • How many quiz questions: QUIZ_LEN in web/index.html.
  • When a topic counts as weak: the weakNow line in recordAnswer.
  • How long a note stays on Lumi's screen: noteUntil = millis() + 4000 in lumi_lamp.ino (milliseconds; re-upload the sketch after changing it).
  • How strict the AI grading is: the system prompt in the /api/quiz/grade route in server/server.js.
  • Which AI model is used: AI_MODEL and AI_FALLBACK_MODEL in .env (see .env.example).

A practice to reuse

Write the rule as something you can observe, then test that exact thing. The PRD said an AI error must keep your quiz progress (prd.md > States and Boundaries), and the checklist turned that into a test: turn off Wi-Fi mid-quiz and check that the quiz continues. Building slice 4 against that rule exposed a real bug: a failed question called quizStop() and ended the quiz. The fix is recorded under Revisions in devpost/checklist.md.

On your next project, before asking an agent to build something, write down what you should see when it works, including when something goes wrong. That gives both of you a clear way to check the result.

Run it again

Start Lumi
  1. In the project folder, run npm install once, then npm start.
  2. Open http://localhost:8787 in Chrome or Edge.
  3. Plug in the lamp and click Connect lamp. Close the Arduino Serial Monitor first; only one program can use the port.
